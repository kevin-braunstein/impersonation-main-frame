The same five values are shown for three different frames in this tab: the Main frame's table is below; the local iframe's and OOPIF's own tables are rendered inside their respective <iframe> boxes further down this page (open each one's own devtools context, or view it standalone, to inspect it directly). In every table, the Initial column is captured synchronously in that frame's very first <script> tag; the Current column is re-collected every second. Current is highlighted green when it matches Initial and red when it doesn't. Any call that failed or returned an unsupported/undefined result (e.g. window.fireglassGetRendererPolicy not being defined) is highlighted red regardless of whether it matches, since a consistent failure is still a failure. The navigator.userAgentData (direct property reads) row additionally gets an orange outline whenever its value differs from navigator.userAgentData.toJSON() in that same snapshot - Chromium's native toJSON() reads an internal engine slot rather than the JS-visible getters, so an override that patches the getters but not toJSON() will leak a different, un-overridden value to anything that calls .toJSON() or JSON.stringify(navigator.userAgentData).

Note: navigator.userAgentData's high-entropy values (e.g. full version list, platform version) can only be read asynchronously per spec, so they only ever appear in the Current column — never in Initial, and that's expected.
